# make-knowledge-cards

把文章或本地笔记变成一组**知识卡片**的开源 Skill。适用于 WorkBuddy，以及兼容 OpenAI 格式的 Agent 运行时。

## 一、项目解决什么问题

长文、文档、笔记读得快忘得也快。直接收藏或整段高亮，复习时还要重新读一遍，效率很低。

本 Skill 解决的是**「读得懂但记不住、存得下但找不着」**的问题：它把一篇长文自动蒸馏成 5~8 张结构化的知识卡片，每张只讲一个点，带「核心知识 + 大白话解释 + 例子/自测」。这样既能快速抓住重点，也方便日后像翻卡片一样复习，而不必重读原文。

它刻意**不**做花哨的事：不抓取网页、不解析 PDF、不导出 Anki、不做图形界面——只聚焦「文本 → 卡片」这一件有用的事，且保证不编造、不凑数、不重复。

## 二、主要功能

- **两种输入**：直接粘贴文章文本，或指定本地 `.md` / `.txt` 文件路径。
- **结构化卡片**：每张卡片固定包含四部分——标题、核心知识、简明解释、例子或自测问题。
- **诚实的卡片数**：默认 5~8 张；素材不足就不强行凑数（少于 5 张会标注「素材较少」）。
- **一张卡片一个知识点**：绝不把两个无关点塞进同一张卡。
- **去重合并**：原文重复表达同一观点时，合并为一张卡（标注「已合并重复表述」）。
- **不编造**：只提炼原文已有信息，绝不添加原文没有的事实、数字或结论。
- **纯 Markdown 输出**：单一文档，方便复制、粘贴、二次编辑或转存。

> 暂不支持：网页抓取（URL）、PDF、Anki 导出、图形界面。遇到这些输入会明确说明限制，并请用户改用 Markdown / 纯文本。

## 三、安装方法

本仓库是一个标准 Skill 目录，按使用场景放置即可，**无需编译、无需依赖**。

### 方式 A：用于 WorkBuddy（推荐）

把 `skills/make-knowledge-cards/` 整个文件夹复制到以下任一位置：

- **用户级（所有项目通用）**：`~/.workbuddy/skills/make-knowledge-cards/`
- **项目级（仅当前仓库协作共享）**：`<你的项目>/.workbuddy/skills/make-knowledge-cards/`

示例（以用户级为例）：

```bash
# 假设本仓库已克隆/解压到 ./make-knowledge-cards-repo
cp -r ./make-knowledge-cards-repo/skills/make-knowledge-cards ~/.workbuddy/skills/
```

放入后，在 WorkBuddy 对话中直接提出「帮我做成知识卡片」之类需求即可自动触发；也可在专家/技能中心手动查看。

### 方式 B：用于 OpenAI 兼容的 Agent 运行时

本 Skill 提供了 `agents/openai.yaml` 清单（含名称、描述、模型与指令）。将其作为 Agent 定义加载到对应的运行时，并确保运行时能读取同目录下的 `SKILL.md`，即可按其中的工作流执行。

> 说明：当前为本地开源形态，尚未发布到任何市场，因此没有 `pip install` 或一键安装命令。如需打包分发，可运行 `package_skill.py` 生成 zip。

## 四、使用方法

### 1. 直接粘贴文章

把文章内容贴给 Agent，并说明需求，例如：

> 帮我把下面这篇讲 Git 合并的文章做成知识卡片：  
> （粘贴正文……）

### 2. 指定本地文件

把 `.md` 或 `.txt` 文件放到工作区，告诉 Agent 路径即可：

> 把这个文件整理成知识卡片：samples/technical_git.md

Agent 会读取文件内容，并按 `SKILL.md` 中定义的工作流生成卡片。

## 五、输入 / 输出示例

**输入（粘贴文本）**

```
HTTP 缓存用头部控制。Cache-Control 用 max-age（秒）设定缓存时长。
ETag 让服务器通过条件请求校验缓存。304 表示"用你的缓存"。
Vary 告诉缓存响应取决于某个请求头，如 Accept-Encoding。
```

**输出（Markdown）**

```markdown
# 知识卡片：HTTP 缓存基础

> 来源：粘贴文本 ｜ 卡片数：4

## 卡片 1：Cache-Control 控制最大年龄
- **核心知识**：`Cache-Control` 用 max-age（秒）定义响应可被缓存的时长。
- **简明解释**：客户端在该秒数内可复用缓存，无需重新请求。
- **例子或自测问题**：自测：max-age=60 表示缓存多久内有效？

## 卡片 2：ETag 用于条件校验
- **核心知识**：`ETag` 是资源的标识，服务器用它做条件请求校验缓存。
- **简明解释**：客户端带上 ETag 询问"是否变化"，服务器比对后决定。
- **例子或自测问题**：自测：什么情况下服务器会返回 304？

## 卡片 3：304 表示复用缓存
- **核心知识**：状态码 304 表示资源未变，客户端应使用本地缓存。
- **简明解释**：这避免了重复传输相同内容，节省带宽。
- **例子或自测问题**：例子：浏览器收到 304 后直接渲染已存的页面。

## 卡片 4：Vary 描述依赖的请求头
- **核心知识**：`Vary` 告知缓存响应取决于某个请求头（如 Accept-Encoding）。
- **简明解释**：不同请求头可能得到不同响应，需分别缓存。
- **例子或自测问题**：自测：为什么压缩与否会影响缓存键？
```

素材较少时卡片数会少于 5（并标注「素材较少」）；存在大量重复表述时会先合并再出卡（标注「已合并重复表述」）。

## 目录结构

```
skills/make-knowledge-cards/
├── SKILL.md            # 完整工作流与质量规则（权威定义）
└── agents/
    └── openai.yaml      # OpenAI 兼容的 Agent 清单（指向 SKILL.md）
```

`samples/` 目录下附带了 4 类测试文章（技术、科普、单句、重复）及其生成结果，可用于回归验证。
